# HPC methodology

The oracle is `sequential` with `single-single`. Single refers to one eligible OS logical processor, not guaranteed exclusive physical-core ownership. `single-multi` uses real threads pinned to that processor and demonstrates scheduling contention. `multi-single` is one migratable worker; it is not simultaneous multicore execution. `multi-multi` uses independent group workers. OpenMP uses genuine parallel loops. Hybrid CPU+OpenMP computes causal features/inference in parallel before serial deterministic matching.

Input order is never split into independent time chunks for a dependent book. Work is partitioned by instrument, or adjacent pairs for statistical arbitrage. Aggregation follows fixed indices. A benchmark rejects a candidate when event counts, fills, orders, deterministic checksums, P&L, equity, fees, or drawdown differ from the sequential reference.

Each engine receives the same dataset, model, strategy, cost/risk settings and initial capital. Warmups are excluded from timing samples. Native `wall_seconds` spans feature-buffer work, feature/inference processing, matching, and in-run aggregation. It excludes CSV load and initial native work-index setup. `profiling.load_seconds` records input loading; Python `process_seconds` includes process creation/load/output and `orchestration_seconds` additionally includes validation, hashing, and initial persistence. Report both scopes when interpreting end-to-end performance.

Throughput = events/native wall time. Speedup = baseline median/candidate median. Homogeneous worker efficiency = speedup/workers. MPI uses ranks×workers per rank; heterogeneous CPU/GPU hybrid efficiency is left null because its denominator is not a homogeneous processor count. Karp–Flatt's inferred serial fraction `(1/S-1/p)/(1-1/p)` is descriptive and can be distorted by overhead. Amdahl predicts `1/(s+(1-s)/p)` for fixed work; Gustafson predicts `p-s(p-1)` for scaled work. Neither is reported as measured data.

Samples have median, mean, sample standard deviation, and a 95% Student-t interval for up to11 samples (normal approximation above11). One repeat has no confidence interval. Environment noise, thread startup, small work partitions, memory bandwidth, and oversubscription can dominate; a speedup below1 is a valid observation. Benchmark jobs have no live UI callback.

Event p50/p95/p99 are sampled CPU decision+matching latencies and exclude GPU preprocessing. These are computation timings, distinct from configured exchange-latency nanoseconds. CUDA reports H2D/kernel/D2H separately and remains compared using its full native region. MPI communication is separately accumulated, including actual collectives. Unsupported OS counters are null, not invented measurements.

Strong scaling: `hftlab scaling --dataset ... --engine threaded --workers 1,2,4 --repeats 3`. Weak scaling adds `--weak --events-per-worker 10000` and grows independent instruments and events with workers. Each generated workload gets its own same-input sequential oracle. Use adequate instrument/group counts to occupy workers; pair strategies have half as many independent groups.

Native simulation is an in-memory workload: event AoS records, stable index arrays, per-event equity deltas and book storage. Hybrid additionally allocates contiguous six-feature and three-probability double buffers (72bytes/event before other arrays). Generation and validation are streaming, but 100million-event simulation is not a bounded-memory streaming engine. Avoid presenting the generator's scale as proven simulator capacity.
