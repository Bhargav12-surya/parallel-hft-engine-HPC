# Ten-phase implementation map

This is the C edition of the requested project. Every phase has functioning code or deliverables. The table distinguishes the implemented scope from acceptance items that remain outside this edition; it is not a claim that every sentence of the original C++/CUDA specification has been met.

| Phase | Delivered C implementation | Differences / boundaries |
|---|---|---|
| 1 — core | CMake C17, Philox known-answer test, deterministic math, timers, SPSC queues, fixed order slots, FIFO price levels and scan reference, integer accounting, market generator, two serial engines, configuration and regression tests | Reference uses a fixed slot scan rather than deliberately allocating per event. Fixed book range does not recenter. |
| 2 — desktop/market | Win32/GDI and X11 desktop, background service, triple-buffer snapshots, candle/depth/heatmap/current-fill views, run/pause/stop | Native C UI replaces ImGui/ImPlot. Detailed market view is symbol 0; no full scrolling market tape or connection to live data. |
| 3 — strategies/threads | Ten traditional strategies, shared risk checks, pair-owned worker queues, CPU affinity, C model APIs | TWAP parent execution is implemented; volume-participation/VWAP scheduling and independent statistical pair selection are not. Parameters beyond cycling controls use JSON. |
| 4 — OpenMP/analytics | Static/dynamic/guided schedules, covariance and cache blocking, Cholesky, CG, k-means, correlated Monte Carlo, atomic/critical/reduction/false-sharing demonstrations | Deterministic analytics reductions may limit peak speed. There is no unsafe data-race demonstration. |
| 5 — MPI/hybrid | C worker, pair-aware cyclic/contiguous decomposition, derived event/order/fill datatypes, Bcast/Scatterv/Gatherv/Allreduce, Isend/Irecv central state exchange, distributed CG, synchronous data-parallel SGD, JSON-lines process launcher and cancellation | Central topology centralizes state communication; it is not a rank-0 matching gateway routing every order. Single-host MPI was tested; multi-node transport was not. |
| 6 — device | OpenCL C full market/decision simulation, scalar/local-tiled covariance, MLP inference/backprop/update, Q episodes, layout checks, one/two compute queues, optional pinned staging, explicit timing; optional NVIDIA C library covariance/Gaussians | OpenCL replaces custom CUDA. No CUDA Graphs, cuDNN, GPU occupancy instrumentation, GPU CG or NCCL. GPU market state is one fixed struct per symbol rather than a compact SoA. Actual GPU/NVIDIA validation is pending. |
| 7 — AI | 32→64→32→3 MLP with backprop/SGD, chronological holdout and gap, online observed features, binary model persistence, 81×9 Q table, k-means/UCB selector; CPU/OpenMP/OpenCL training and MPI SGD | Q tables train independently and average across episodes; convergence is not guaranteed. Models are teaching examples, not claims of predictive profit. |
| 8 — benchmarks/results | S1–S8 command paths, repeated simulation runs, hash verification, worker/latency/timing metrics, JSON/CSV/SVG/PNG exports, GUI suite runner, actual equity curve, latency-coupled orders | No radar/leaderboard/auto-insight GUI panels. Analytic S4–S7 drivers currently time one invocation per call rather than repeated distributions. CPU latency is pair-step, not pure feed-arrival-to-order latency. |
| 9 — cloud/learn | Editable price assumptions/network presets, delayed execution, simulated latency P&L change, lessons, actual embedded source viewer/export, settings and presentation navigation | No cloud provisioning, SSH client, live provider pricing or full interactive notebook. Network delay is simulated, not an actual WAN benchmark. |
| 10 — delivery | Source ZIP, Windows x64 CPU executables, C examples, configs, build/benchmark scripts, CPack ZIP, Inno Setup recipe, architecture/benchmark/cloud documents, report template, viva and validation logs | Windows execution, MSVC build, signed installer, physical GPU and multi-node acceptance remain for the target machine. |

The authoritative validation record is `VALIDATION.md`. Optional backend absence is a capability result, not a successful device test. Configuration keys reserved for a different architecture are documented rather than silently reinterpreted.
